# 1-تعريف ماهو GIT

الهدف من git انه انا عايز اعمل track لل changes في ال files على فترة زمينة معينة لو حصل اي تغييرات مش مطلوبة اقدر ارجع ل version قديمة.

وكمان لو اكتر من حد شغال على نفس المشروع ازاي هنعرف ننظم الدنيا.

ال**Version control** هو انه يكون عندي control على ال History بتاع التغييرات اللي حصلت في ال files في المشروع بتاعي ايا كان نوع الfile ده.


# 2-انواع ال Version control systems

## Local version control systems

## Central version control systems

![[git2.jpg]]

ممكن تكون شغال في شركة انت وزملائك كلكم شغالين علىproject للشركة ويكون الsource code بتاع المشروع موجود في server في الdata center بتاعك جوه الشركة وكلكم بتدخلوا على الserver ده علشان تعملوا التعديلات على المشروع  - العمليات الأساسية زي commit وupdate بتعتمد على الاتصال بالـCentral Repository.

لازم تكون على تواصل على طول مع الserver لو فقدت الاتصال بالـServer، تقدر تكمّل تعديل على الـWorking Copy الموجودة عندك، لكن مش هتقدر تعمل العمليات اللي محتاجة اتصال بالـCentral Repository زي Commit أو Update لحد ما الاتصال يرجع.

## Distributed  version control systems

![[git3.jpg]]

شبه  الcentral بس فيه فرق بس هنا مش بيشتغل live على الserver الفكرة هنا انه بينزل copy بيعمل clone فيه فرق بين download و clone هنعرف الفرق قدام بس المهم دلوقت تعرف انه لما بعمل Clone بيكون عندي Local Repository كامل على الجهاز، فأقدر أعمل معظم عمليات Git محليًا من غير ما أكون متصل بالـServer.

بس الفكرة برضوا لو حد رفع تعديلات على النسخة الموجودة في الserver مثلا اقدر انزل التعديلات عندي وانا ممكن اعدل شوية تعديلات وارفعها ده بنسميه Push , انت اه فعلا عملت Clone لكن لسه فيه صله بين النسخة الموجودة على الserver والنسخة الموجودة عندك علشان تسهل عملية الpush وعملية الpull تقدر تعمل Push للـCommits اللي عملتها عندك، وتعمل Pull علشان تجيب التعديلات الجديدة من الـRemote Repository.

مش محتاج تكون متصل بالserver أثناء معظم شغلك لانه بيكون عندك Local Repository وكمان لو فيه لابتوب تاني عليه نفس الproject غير الserver ممكن اعمل من عليه Push او Pull **لو الجهاز التاني متاح ومتعرف عندك كـremote repository**.

وgit بتاعنا من نوع الDistributed وممكن نستخدمه local برضوا عادي.
